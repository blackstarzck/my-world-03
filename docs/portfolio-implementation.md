# 개발자 포트폴리오 구현과 검증

2026년 10월 20~21일 사용자 피드백을 반영한 현재 구현 기록이다. [기존 배치 계획](portfolio-spatial-plan.md)의 세 방과 49개 위치, 95개 프로젝트·사례 항목은 유지한다. 이전 계획의 시적인 제목·설명 패널·액자 면 HTML 투영은 현재 상세 페이지의 기준이 아니다. 공개 배포는 수행하지 않았다.

## 독립 평가에서 확인한 문제

디자인, 채용 개발자, 인터랙션 담당 에이전트가 각각 첨부 화면·프로젝트 데이터·소스를 검토했다. 주 담당자는 [my-world-02](https://my-world-02.vercel.app/)에서 작품 선택, 정면 이동, 전체 화면 상세 전환을 직접 확인했다.

| 관점 | 확인한 문제 | 반영 |
|---|---|---|
| 시각 디자인 | 반복되는 도형과 모형이 실제 프로젝트의 특징을 전달하지 못함. 긴 소개 이미지 전체 축소로 가독성 저하 | 자료는 읽을 수 있는 크기로 스크롤하고 검수된 그림 49점으로 교체 |
| 채용 개발자 | 실제 프로젝트명과 본인의 기여보다 시적 제목·공간이 강조됨. 역할·설계 판단을 평가할 설명이 부족함 | 실명을 제목으로 사용하고, 95개 항목을 개발 사례 구조로 재작성 |
| 인터랙션 | 원근 투영한 iframe의 좁은 viewport가 앱 레이아웃을 압박함. 이동과 설명 패널이 동시에 나타남 | 정면 도착 후 평평한 상세 등장. 그림·체험과 개발 설명을 좌우 배치하고 확대 모드 제공 |

## 현재 사용자 경험

- 01 제품과 사용자, 02 시스템과 개발 프로세스, 03 인터랙션과 실험의 세 방과 49개 전시 위치·95개 프로젝트 항목을 유지한다. 목록에서 하위 프로젝트도 직접 검색·선택할 수 있다.
- 걸어서 작품의 앞쪽 약 3m 안에 접근하면 좌측 프로젝트명과 열기 버튼이 자동으로 표시된다. 벽·패널에 가려지거나 뒤쪽에 있는 작품은 제외한다. 3.5m를 벗어나거나 시선을 돌리면 방 소개로 돌아가며, 인접 작품 사이에서는 거리 여유를 두어 제목이 반복해서 바뀌지 않게 한다. 자동 감지는 카메라나 키보드 초점을 이동시키지 않는다.
- 좌측 제목은 `word-break: keep-all`로 한글 단어를 유지한다. 영역보다 긴 단일 문자열에만 `overflow-wrap: break-word`를 적용한다.
- 공간에서 최초 선택 시 카메라가 정면으로 이동하고 240ms 유지한 뒤, 평평한 크림톤 상세 화면을 380ms 동안 페이드인한다. 상세 내부의 이전·다음과 전체 목록 선택은 같은 페이지의 내용만 즉시 교체하며 카메라는 움직이지 않는다. 모션 감소 설정에서는 최초 전환을 생략한다.
- 기본 화면은 그림이다. 데스크톱에서는 왼쪽 그림·체험 영역을 고정하고 오른쪽 개발 설명만 스크롤한다. 오른쪽 폭은 화면의 40%, 최소 440px·최대 640px이다. 폭 1100px 미만에서는 그림·체험 아래에 설명을 배치한다.
- 설명은 프로젝트명·핵심 요약·확인된 역할과 범위·기술·문제와 제약·핵심 구현과 선택 이유·결과와 근거·체험과 코드 링크 순이다. 담당 역할을 확인하지 못한 항목은 검증된 구현 범위를 보여준다.
- 승인된 웹앱이 있는 프로젝트만 그림 보기·프로젝트 체험 전환을 제공한다. 체험이 없는 프로젝트는 탭 없이 그림과 설명만 표시한다. 크게 보기에서 설명을 접고 그림 또는 웹앱을 전체 가용 화면에 표시한다.
- 그림·체험 전환과 창 크기 변경에도 같은 iframe·입력·주소를 유지한다. 다른 프로젝트·목록·닫기에서는 iframe을 제거한다. 같은 그림의 하위 프로젝트는 카메라 이동 없이 내용을 바꾸고 그림 보기로 돌아간다.
- 닫기 X는 iframe 밖 우측 상단에 유지한다. 닫으면 마지막으로 선택한 작품의 안전한 정면 위치·화각으로 카메라를 즉시 배치하고 해당 작품의 갤러리 조작부에 초점을 둔다. 닫기 카메라 이동과 페이지 페이드아웃은 없다. ‘공간으로 돌아가기’ 버튼은 제거했다. Escape는 확대 복귀 후 X와 같은 닫기 순으로 동작한다. 최초 진입 도중 취소는 진입 전 위치로 복귀하며 늦게 도착한 상세를 열지 않는다.
- 화면 자료 탭·캡처 뷰어·자료 소개 화면·자료 전환 상태·전용 CSS·이미지 다운로드 및 동기화 코드를 제거했다. 설명과 기술 메타데이터만 유지하며, 기존 화면 파일은 output/retired-screen-materials-2026-10-20/에 보관한다.
- 작품에 대하여·관람 포인트·연작 같은 UI 문구와 시적인 프로젝트명을 제거하고 실제 프로젝트명을 표시한다.

## 설명의 작성 기준과 근거

95개 항목을 각기 다른 설명으로 작성했다. 01의 25항목과 02·03의 70항목은 별도 파일로 관리한다. 원본 포트폴리오, 공개 저장소의 README·소스, 로컬 Planit·On the Book·TOPIK 등의 코드를 대조했다.

- TOPIK: 문항별 답안 타입·제출 데이터 경계, 사용자·관리자 간 스키마 계약, 권한과 감사 이력.
- CONNECT BEE: 센서 조회에서 팬·열선 제어로 이어지는 흐름, 하이브리드 패키징·출시, 확인된 실제 담당 범위.
- 문서 통합: 엑셀·DB 컬럼 계약과 프론트엔드·서버 양쪽 변경 지점.
- Planit: 문서 연결·독립 버전, AI 변경 제안의 승인·충돌 확인, SQLite·IndexedDB 복구 구조.
- On the Book: 읽기 위치, 사용자·관리자의 공통 3D 화면, 임시 편집본·발행본, 에셋 보존.
- React 학습 26개: 라우팅·상태 소유권·비동기 요청 등 각 예제의 실제 코드 범위를 구분. 현재 기본 화면이나 마크업만 남은 저장소는 완성된 기능으로 소개하지 않는다.

개인 역할이 확인되지 않는 18항목에는 임의로 담당 범위를 만들지 않았다. QA에서 화면이 표시됐다는 기록을 프로젝트 설명으로 쓰지 않는다. 측정하지 않은 성과, 가공한 트레이드오프, 샘플 수치를 본인 실적으로 추가하지 않았다. 외주·개인·학습·UI 프로토타입의 차이를 유지한다.

## 적용된 그림과 캔버스

검수된 그림 49점을 기존 벽면·패널 39곳과 진열장 10곳에 적용했다. 그림별 전담 에이전트 49명의 평가 기록과 원본 PNG를 보존했다. 39점은 원본 통과, 10점은 한 차례 수정 후 통과한 최종본이다.

화풍은 방별로 통일하지 않고 각 프로젝트에 맞춰 선택했다. 수채·아크릴 참고 무드와 상징·여백을 유지하며 복잡한 개념에는 간결한 포스터·팝아트를 사용했다. 캔버스 앞면 프레임과 매트는 제거했다. 일반 가로 1.65m·끝 벽 2.25m·진열장 1.02m, 비율 7:5, 측면 두께 0.03m다.

## 상세 내부 탐색과 닫기 · 최신 정책

2026-10-21 추가 피드백으로 상세 내부 탐색과 X 닫기의 정책을 변경했다. 우측 상단과 설명 하단의 이전·다음은 같은 상세 DOM을 유지한 채 그림·설명을 즉시 바꾸며 카메라 이동·도착 대기·페이드 전환을 실행하지 않는다. 다른 방의 항목을 전체 목록에서 선택해도 같은 방식이다. 빠른 연속 클릭의 선택을 참조로 추적하고, 탐색 버튼의 키보드 초점을 유지한다.

X와 상세 Escape는 마지막 선택 작품 앞으로 즉시 배치한다. 위치는 `artworkView`가 계산한 충돌 없는 정면 위치·화각이다. 진행 중인 이전 모션을 해제하고 선택·방·갤러리 커서를 일치시킨다. 최초 진입 애니메이션 취소의 원위치 복귀는 유지한다.

- `node tools/verify-detail-navigation.cjs`: 49개 전체 탐색 중 매 프레임 카메라 정지·동일 상세 DOM·내용 변경을 검사한다. 11회 연속 클릭 왕복, 하단 버튼, 다른 방 목록 선택, 다섯 화면 비율, X·Escape 즉시 배치와 진입 취소를 포함한 14개 검사 통과. 결과는 `output/browser-checks/detail-navigation/report.json`.
- `node tools/verify-camera.cjs`, `node tools/verify-close-camera.cjs`: 최신 상세 탐색 검사로 연결한다. 아래 진입 시점 복귀 기록과 42초 녹화는 변경 전 정책의 검증 이력이다.
- `npm test`: 자동 검사 57개 통과. `npm run build`: 통과.
- `node tools/verify-portfolio.cjs`: 실제 On the Book 체험, iframe 유지·해제, 하위 프로젝트 변경, 다섯 화면 크기, 독립 스크롤·키보드 초점을 포함한 26개 검사 통과. 상세 탐색 14개와 합계 40개 브라우저 검사에서 실행 오류가 없었다. 종합 결과는 `output/browser-checks/detail-navigation/verification-summary.json`에 저장한다.

## 카메라 진입·복귀 재검수 · 변경 전 정책 기록

닫기 동작이 선택한 프로젝트의 방 입구로 이동하던 원인을 제거했다. 상세 진입 시 실제 카메라 위치·쿼터니언·화각·오빗 중심과 갤러리 선택 상태를 한 번 저장한다. 상세 내부의 이전·다음, 하위 프로젝트, 전체 목록에서 다른 프로젝트를 선택해도 최초 진입 시점을 유지한다. 최종 닫기와 진입 취소는 이 시점으로 돌아온다.

| 시나리오 | 검증한 동작 |
|---|---|
| 로비·각 방에서 목록 진입 후 우측 X | 원래 위치·시선·화각·갤러리 UI 복원 |
| 작품 직접 클릭 후 이전·다음·다른 방 프로젝트 | 첫 상세 진입 시점 유지 |
| 상세에서 목록 열고 취소 | 기존 상세와 카메라 유지 |
| 자유 이동·시선 변경 후 진입 | 임의의 보행 위치 복원, 리사이즈로 옛 작품에 끌려가지 않음 |
| 전체 공간에서 진입 | 기존 오빗 위치·중심·지붕 표시 복원, 감쇠 잔여 이동 없음 |
| 이동 중 목록 열기 | 배경 이동과 타임라인 정지, 닫으면 같은 지점부터 재개 |
| 접근 중 취소 | 진입 시점 복귀, 지연된 상세가 나타나지 않음 |
| 복귀 중 재진입 | 현재 위치를 새 진입 시점으로 사용, 이전 복귀 콜백 무효화 |
| 상세 중 화면 크기 변경 | 상세 DOM 유지, 원래 위치·시선 복원, 필요한 경우 그림 시야각 조정 |
| 모션 감소 설정 | 같은 복귀 결과를 즉시 적용 |

사선 패널 모서리를 12cm 간격의 검사 지점 사이에서 통과하던 경로를 추가로 발견했다. 경로 구간의 중간과 주변 여유 폭을 확인하고 필요한 구간을 세분화한다. 자동 이동과 직접 보행에 같은 구간 검사를 적용했다. 벽과 진열장 모서리 가까이에 서 있어도 안전하게 빠져나갈 수 있는지 회귀 검사한다.

- `node tools/verify-camera.cjs`: 실제 Chromium에서 12개 진입·복귀 시나리오 통과. `output/browser-checks/camera-audit/scenarios.json`.
- `node tools/audit-camera-routes.mjs`: 49개 작품 간 모든 순서의 이동과 방 입구 왕복을 다섯 화면 비율로 검사. 최종 수치와 결과는 `output/browser-checks/camera-audit/routes.json`.
- `tests/camera-session.test.js`: 복귀·취소·재진입·오빗·일시 정지·리사이즈·수동 이동·좁은 출발점·모서리 통과 회귀 검사.

최종 결과: 자동 검사 41개, 실제 진입·복귀 12개 시나리오, 기존 웹앱·상세 회귀 검사 26개, 빌드가 모두 통과했다. 다섯 화면 비율에서 작품 간 이동과 입구 왕복 총 13,965개를 확인했다. 중복을 제외한 경로 5,586개와 정방향·복귀 모션 11,172개에서 1,288,400개 시점을 검사했고 충돌·비정상 수치·잘못된 도착 지점은 없었다. 최대 회전 속도 약 2.407rad/s와 이동 속도 22m/s는 기존 설정 범위 안이다. 종합 결과는 `output/browser-checks/camera-audit/verification-summary.json`에 있다.

## 근접 선택과 복귀 보완 · 변경 전 상세 닫기 정책 기록

앞선 검사는 경로의 안전성과 마지막 위치 복원을 확인했다. 근접 선택에서도 보행용 진행 방향과 최소 1.8초 타임라인을 사용해 뒤로 물러나면서 돌아보는 문제가 남아 있었다. 가까운 구도 조정은 보행 경로와 별도로 처리한다.

- `src/world/artwork-approach.js`: 작품 앞의 가까운 위치이고 구간 전체가 안전하면 직선 구도 조정을 선택한다. 벤치가 이상적인 감상 위치를 가로막으면 벤치 앞에서 멈추고 그림 네 모서리를 포함하도록 화각을 넓힌다. 원거리·막힌 경로는 기존 보행 경로 탐색을 유지한다.
- `src/world/camera-motion.js`: 이동 방향과 시선을 분리한다. 작품을 바라보면서 정면으로 정렬하고, 현재 시선이 중심에서 벗어나 있어도 점프 없이 맞춘다. 짧은 이동에 1.8초 하한을 적용하지 않으며 거리·실제 회전 속도·화각 변화에 따라 시간을 정한다. 대표 정면 접근은 약 0.55초다. 이미 정면과 화각이 맞으면 이동을 생략한다.
- 첫 상세 진입 모션과 실제 재생 구간을 저장한다. 같은 진입 상태에서 닫으면 위치·시선·화각이 같은 경로를 되짚는다. 이동 중 취소는 지나온 구간만 되돌리며, 출발과 도착에서 속도를 낮춘다.
- 이전·다음, 다른 방, 창 크기 변경 후에는 현재 카메라 위치에서 최초 진입 위치로 복귀한다. 예전 진입 모션의 끝으로 순간 이동하지 않는다. 인접 프로젝트에서는 직선이나 짧은 안전 우회 경로 모두 보행용 회전과 시선을 분리한다. 패널 모서리 주위의 굽은 경로는 가속도를 고려해 이동 시간을 정한다.
- 일시 정지는 실제 재생 구간에 포함하지 않는다. 복귀 중 다시 진입하면 이전 완료 콜백을 폐기하고 새 진입 위치를 유지한다. 모션 감소 설정도 같은 최종 위치·시선·화각을 복원한다.

검증 도구와 결과:

- `node tools/audit-close-camera.mjs`: 실제 벽면·사선 패널·진열장 49개에서 다섯 화면 비율과 정면·좌우 접근을 검사한다. 근접 진입 735개, 부분 취소·전체 복귀 2,940개, 이전·다음 프로젝트에서 복귀 490개, 총 374,609개 시점이 통과했다. 인접 복귀 중 261개는 패널·가구 주변의 짧은 우회 경로를 포함한다. 검사한 근접 진입 735개 모두 안전한 직선 구도 조정을 사용했다. 충돌·잘림·시선 이탈·비정상 수치가 없고 최대 회전 속도는 약 2.579rad/s다. 결과는 `output/browser-checks/close-camera/geometry.json`.
- `node tools/verify-close-camera.cjs`: 실제 캔버스 클릭, 우측 X, Escape, 접근 중 취소, 이전·다음 후 닫기, 다음 프로젝트로 이동 중 취소, 모바일 세로·가로 화면을 포함한 브라우저 검사 13개가 통과했다. 인접 프로젝트에서 닫을 때 불필요한 회전이 없는지도 확인한다. 매 프레임 카메라 위치·시선·화각·이동 방식을 `output/browser-checks/close-camera/traces.json`에 저장한다. 결과는 같은 폴더의 `browser.json`.
- `tests/camera-session.test.js`: 근접 정면·비스듬한 접근, 0/32/150/350ms 취소, 시선 중심 보정, 일시 정지, 화면 크기 변경, 복귀 중 재진입, 인접·다른 방 프로젝트 탐색 후 복귀를 포함한다. 전체 자동 검사 55개와 빌드를 확인한다.
- 기존 `node tools/verify-camera.cjs`의 12개 시나리오도 다시 통과했다. 기존 전체 공간·목록 진입·자유 보행·초점 복귀 동작을 유지한다.

최종 결과: `npm test` 55개, 브라우저 검사 25개, `npm run build` 통과. 실행 오류는 없었다. 브라우저 검사는 기본 GPU 렌더링을 사용하며 소프트웨어 WebGL 검사가 필요하면 `CPU_WEBGL=1`을 설정한다. 요약은 `output/browser-checks/close-camera/verification-summary.json`에 저장한다.
